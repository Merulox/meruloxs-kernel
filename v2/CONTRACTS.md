# Contracts

Contracts are boundaries between planes. They replace provider-specific handoff prose with stable, observable interfaces.

## Contract types

### Intent contract

Defines the world-state change before execution. Use [templates/intent-contract.md](templates/intent-contract.md).

Required fields:

- stable work ID and title;
- accountable lead;
- selected mode and risk tier;
- repository/workspace and ownership boundaries;
- dependencies and approval flags;
- positive, negative, and boundary scenarios;
- public invariants, forbidden outcomes, and evidence expectations;
- oracle mode, owner, and `public_spec_hidden_checks` visibility when `independent_oracle` is required;
- disposable-workspace, explicit-mount, oracle-exclusion, pinned-runtime, credential-reference, egress, and host-evidence policy when protected execution is required;
- rollback/failure behavior;
- non-goals;
- repair limits.

An intent contract is ready only when an uninvolved verifier could determine whether the work succeeded without asking what the author meant.

### Worker contract

A worker contract is generated by the lead from the intent contract. It must contain:

```text
TARGET       exact files, symbols, domain, or artifact
CHANGE       bounded work and interface contract
NON-GOALS    explicit exclusions
PUBLIC SPEC  every scenario, invariant, forbidden outcome, and evidence expectation
VISIBILITY   executor-visible gates and isolation profile only
ACCEPTANCE   observable slice result
VERIFY       slice-local public checks; no project-wide suite
OUTPUT       typed result or apply/merge policy
```

Workers start blank. Do not reference conversation context they cannot access. A worker contract may narrow the intent contract but never broaden it.

For `public_spec_hidden_checks`, the worker contract is complete without private material: it includes all public requirements and executor-visible checks, but excludes oracle source, path, content, private fixtures, verifier-only gate entries, and oracle credentials. `protected_paths` expresses write ownership only and must never be used to disclose an oracle locator.

### Verifier contract

A verifier receives through a verifier-only channel:

- the frozen intent contract and public invariant IDs;
- the verifier-owned oracle reference and oracle identity/hash;
- the resulting diff/artifact;
- executor-visible deterministic gate results;
- the host-owned isolation manifest, absence proof, and real-system evidence.

It must:

1. map every acceptance claim to evidence;
2. try to falsify positive and negative scenarios;
3. check forbidden changes, gate weakening, and oracle identity;
4. confirm that the oracle was absent from every executor namespace and that host execution began only after executor exit;
5. distinguish `implementation_failure`, `oracle_failure`, `ambiguous_requirement`, `environment_failure`, and `runner_failure`;
6. return `PASS`, `FAIL`, or `ESCALATE`, the stable failure class, the failed public invariant, and a minimal counterexample when available;
7. disclose no oracle source, path, private fixture content, or reconstructive check detail to the executor.

The verifier does not rewrite the implementation unless reassigned under a new worker contract.

### Run record

The control plane records one run independently of work-item status:

```yaml
run_id: string
work_id: string
contract_version: string
mode: direct | fan-out | mission | routine
parent_run_id: string | null
agent_session: string | null
model: string
runtime_identity: string
workspace: string
workspace_disposition: primary | isolated | disposable
mount_manifest_artifact: string | null
oracle_exclusion_verified: boolean | null
credential_refs: []
egress_policy: string | null
host_evidence_uri: string
started_at: timestamp
executor_finished_at: timestamp | null
oracle_started_at: timestamp | null
oracle_hash: string | null
verifier_verdict: pending | not_required | PASS | FAIL | ESCALATE
failed_public_invariant: string | null
minimal_counterexample_artifact: string | null
finished_at: timestamp | null
status: running | succeeded | failed | blocked | cancelled
attempt: integer
artifacts: []
error_class: string | null
```

A succeeded run means the process completed its contract. It does not mean the work item is verified or closed.

### Evidence bundle

The evidence bundle is the completion interface between execution, oracle, control, and governance planes. Use [templates/evidence-bundle.md](templates/evidence-bundle.md).

It contains:

- environment, pinned runtime/profile, workspace, and revision identity;
- changed artifacts and ownership check;
- raw gate commands, outcomes, and artifact paths;
- executor mount allowlist and proof that verifier storage was absent;
- credential reference and egress policy identities, never credential values;
- worker-exit and host-side oracle-execution ordering;
- host-recorded oracle identity/hash and structured verdict;
- real-system exercise and observed resulting state;
- independent verifier verdict when required;
- approvals and containment evidence;
- unresolved limitations;
- final work-state recommendation.

## Evidence quality

Preferred evidence is deterministic and externally observable:

1. state or output from the real target interface;
2. reproducible command with exit status;
3. structured logs, traces, screenshots, video, or metrics;
4. calibrated verifier judgment;
5. implementation-agent narrative.

Higher-numbered evidence cannot substitute for missing lower-numbered evidence when the lower form is feasible.

## Contract changes

After execution begins:

- clarification that does not alter behavior is appended with timestamp and author;
- scope, acceptance, risk, side-effect, or gate changes return the item to `proposed` or `needs_input`;
- active descendants stop if their contract is affected;
- completed evidence is retained but marked against the superseded contract version.
- public scenarios, invariants, forbidden outcomes, or evidence expectations cannot be weakened after execution begins without a new contract decision and version;
- protected oracle changes also create a new verifier-approved oracle identity/hash; prior run and evidence records remain bound to the version they actually used.
